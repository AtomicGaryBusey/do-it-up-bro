# Optional local federation

`Do it up, Bro --federate: <goal>` requests the installed `dub` supervisor. Check `dub --help` and run `dub federate --dry-run "<goal>"` to inspect selected providers and work orders. Use argument arrays when invoking from code; never interpolate untrusted goals into a shell command. If the supervisor is absent, explain that limitation and continue useful native work; do not invent an installation or unofficial provider CLI.

Federation launches provider roots through documented local CLI interfaces. Each root may have different permissions, authentication, orchestration, and accounting. Use existing supported login; never collect credentials, bypass quotas, or presume a subscription covers every model.

v0.1 is an artifact-based advisory federation: provider roots receive distinct analytical work orders. Inspect its run metadata, individual outputs, failures, and synthesis handoff before integrating a result. It does not automatically apply child-generated code or certify correctness. Root concurrency limits do not bound native child-agent fan-out.

Retain successful results when a provider fails. Distinguish unavailable, failed, timed-out, and completed work. A chosen host must adjudicate the artifacts, validate evidence, resolve contradictions, and execute any separately authorized implementation. Campaign checkpoints and interactive escalation remain host-level protocol behaviors; do not assume the supervisor supports live resume or escalation commands.
